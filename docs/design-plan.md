# 数字机房地布局图自动化生成 —— Agent 化改造方案

> 版本：v0.1 草案（供评审）
> 目标读者：项目负责人 / 算法负责人
> 编制日期：2026 年 8 月

---

## 0. 执行摘要

当前流程为：

```
3DGS 重建 → 2D 标注设备 → 训练 2D 分割 → lift 到 3DGS → 提取机柜 → 3D BBox → 投影 2D 布局图 → 人工返工
```

两个核心瓶颈：

1. **2D 标注成本高**：采集视角上千张，标注量随视角数线性放大，且同一机柜被重复标注数百次；换机房/换设备类型需重标重训。
2. **分割噪声大**：box 偏大 / 漏检 / 错检 / 联排切分不全，需人工逐一返工。

本方案不改动 3DGS 重建环节，而是：

- 用 **与设备类型无关的粗分割**（superpoint 自底向上合并）替代 "2D 标注 + lift" 作为候选锚点来源；
- 用 **确定性几何规则 + 领域先验** 消掉大部分错误；
- 用 **VLM 作为判别裁判 + 几何工具执行** 的 agent 循环处理残疑难案例；
- 用 **人工只在 3D 层面复核**，且复核结果自动积累为高质量 3D 标注，反哺模型，形成飞轮。

核心判断：**VLM 只做判别和离散选择，精确坐标由几何算法产出**。这是本方案能落地的关键，也是与"让 VLM 直接输出坐标"类方案的本质区别。

## 1. 现状与痛点

### 1.1 现状 pipeline

```
多视角采集 → 3DGS 重建
   → 标注 2D 设备图（上千张）
   → 训练 2D 分割模型
   → 2D → 3D lift / 特征聚合
   → 3DGS 场景实例分割
   → 提取机柜等设备实例
   → 预估初始 3D BBox
   → 投影到 2D 形成布局图
   → 人工逐区域返工
```

### 1.2 痛点清单

| 痛点 | 根因 | 影响 |
|---|---|---|
| 标注慢 | 标注对象是 2D 图，量 ∝ 视角数 | 每机房数天至数周 |
| 重训频繁 | 2D 分割域敏感，换设备/机房需重标 | 不可扩展 |
| box 偏大 | 分割边界含背景/相邻设备 | 布局图不精确 |
| 漏检 | 遮挡、视角不足、特征弱 | 布局图缺设备 |
| 错检 | 相似物体（空调、门、柱子）误判 | 布局图多设备 |
| 联排切分不全 | 相邻机柜分割粘连 | 需要人工切分 |
| 返工重活 | 人工在 2D 图上反复微调 | 人力成本高 |

### 1.3 核心观察

1. **设备和视角数量不对等**：一个机房的机柜/服务器/空调数量是"百"量级，而采集视角是"千"量级。人工实际上为同一个设备标注了数百次。
2. **机房是强结构化场景**：机柜尺寸标准（如 600/800mm 宽）、成排摆放、方向一致、间距规律、底面贴地。大量错误可用确定性规则消除。
3. **返工本质是"判别"而非"生成"**：人工返工时看的证据是 3DGS 渲染图 + 2D 投影图，并回答"这个 box 对不对 / 该切 / 该扩 / 该删"。这比"从零分割"容易得多，且更利于跨机房泛化。
4. **返工历史即高质量标注**：最终布局图是准确的，意味着人工返工过程本身就在产出精确的 3D 标注。只是目前未被利用。

## 2. 方案设计原则

### 2.1 分层架构：确定性打底，agent 兜疑难

```
确定性规则 + 领域先验（消掉大部分错误，不依赖任何模型）
        ↓
几何工具 + VLM 判别（处理真正难判断的案例）
        ↓
人工只复核低置信度项（不再全量返工）
```

### 2.2 关键原则

1. **VLM 不做精确定位**：VLM 回答判别性问题（"这是一个完整机柜吗？"），精确坐标由几何算法产出。
2. **粗分割高召回**：宁可多给候选，也不漏掉设备。多出的候选由规则/agent/人工筛掉；漏掉的设备谁都看不见。
3. **验证是闭环**：每次修复后重新渲染并把 box 叠加回视图，再验证一次，通过才接受，否则回滚。
4. **可逐步降本**：方案分四阶段，每阶段独立产生价值，且都有明确的进入下一阶段的判据。

## 3. 整体数据流

```
3DGS 重建（现有）
        ↓
┌──────────────────────────┐
│ 阶段A：粗分割（候选锚点）     │
│  superpoint + 自底向上合并 │
↓下
┌──────────────────────────┐
│ 阶段B：确定性规则后处理      │
│  尺寸/对齐/支撑度/行结构     │
└──────────────────────────┘
        ↓ 候选 box 集合
┌──────────────────────────┐
│ 阶段C：Agent 修复循环       │
│  取证 → VLM 诊断 → 选动作   │
│  → 几何工具执行 → 验证      │
└──────────────────────────┘
        ↓ 置信度标记
┌──────────────────────────┐
│ 阶段D：人工 3D 复核         │
│  仅低置信度项，3D 界面操作    │

        ↓

        ↓
回馈：训练 / 微调 3D 检测分割模型（飞轮）
```

## 4. 阶段A：粗分割（候选锚点）

### 4.1 目标

从 3DGS 输出的点云 / Gaussian 中心，产出**高召回**的候选设备体，作为后续所有环节的锚点。**不追求精度，只求不漏。**

### 4.2 做法（借鉴 FoundObj 的 superpoint 思想，去 RL 化）

```
3DGS → 导出点云（或 Gaussian 中心 → 点）
        ↓
过分割成小 superpoint（Felzenszwalb / Graph-based 分割）
        ↓
按领域规则合并成候选体：
  法线相似（同一平面性）
  高度连续（同一柜列）
  属于同一行结构（沿行方向对齐）
        ↓
候选合并后拟合 3D BBox
```

### 4.3 为什么可以去掉 RL

FoundObj 用 RL 是因为"任意物体"的合并策略无法手写。机房设备高度标准化，合并规则可手写：

```
候选合并终止条件：
  宽度 ≈ 600/800mm 整数倍
  深度一致（同一行柜深相同）
  底面贴地
  方向与行方向一致
```

### 4.4 与"2D 标注 + lift"的关系

- 阶段A **替代** 训练 2D 分割 + lift 作为候选来源。
- 已积累的 2D 标注数据仍有用：可作为初始伪标签先训练一个单类检测器提供更稳的候选，后续再让位于纯几何粗分割。
- 本阶段无需人工标注，可扩展到任意新机房 / 新设备类型。

### 4.5 输出

```
候选设备 BBox 集合（高召回，可能含误检）+ 每个候选的置信度
```

## 5. 阶段B：确定性规则后处理

直接用领域先验和确定性规则消掉一部分错误，**不依赖任何模型，成本极低**。这是本方案最容易被低估、但性价比最高的一环。

### 5.1 规则清单

| 规则 | 作用 | 对应痛点 |
|---|---|---|
| 标准尺寸过滤 | 长宽高 / 长宽比符合机柜标称 → 否则候选删 / 标记 | 错检、box 偏大 |
| 行对齐过滤 | BBox 主轴与 RANSAC 拟合行方向对齐 | box 偏斜 |
| 底面贴地检查 | 候选底面接近地平面 | 错检 |
| 点支撑度检查 | BBox 内点云覆盖率 < 阈值 → 候选删 | 错检、box 偏大 |
| 行结构补全 | 沿行方向检测空隙，空隙处有点云密度但无 box → 候选漏检 | 漏检 |
| 联排等分 | 行方向宽度 ≈ 600/800mm 的整数倍 → 自动等分 | 联排切分不全 |
| 间距规律 | 同排相邻设备间距符合预期 → 补/删 | 漏检、错检 |

### 5.2 评估方式

阶段B 完成后，统计它能消掉多少返工量（对比历史人工返工记录）。目标是消掉 40–60% 的返工。

---

## 6. 阶段C：Agent 修复循环

处理阶段B 处理后仍无法确定的疑难案例。这是 agent 化的核心部分。

### 6.1 工具集（重点开发资产）

每个工具都是可测试、可独立验证的确定性几何算法。VLM 只调用这些工具，不直接改坐标。

| 工具 | 作用 |
|---|---|
| `render_view(region, viewpoint)` | 从 3DGS 渲染指定区域（正面 / 斜45° / 俯视） |
| `topdown_density(region)` | 局部点云俯视密度图 |
| `fit_box_to_points(seed)` | 给种子区域，按密度边缘 + 平面拟合产出精确 BBox |
| `split_row(box, width_unit)` | 按标准柜宽切分联排 |
| `check_completeness(box)` | 中心场一致性 → 检测粘连 / 不完整 |
| `check_support(box)` | box 内点密度 / 覆盖率指标 |
| `row_structure()` | 行线、间距统计、空隙列表 |
| `overlay_boxes(image, boxes)` | 渲染图上叠加 box 边框，供 VLM 复检 |

### 6.2 Agent 循环

```text
初始 box 集合
        ↓
┌─ 修复循环（每 issue 一次，限最大重试 2–3 次）────┐
│ 1. 取证：render_view(region) + topdown_density │
│ 2. VLM 诊断：漏检 / 过大 / 联排 / 误检 / 正常？   │
│ 3. VLM 选动作（离散，从动作空间选）：            │
│    split(box, n) / shrink_to_fit(box)         │
│    add_box_at(gap) / delete(box) / merge(box1,b2)│
│ 4. 几何工具执行：精确坐标由算法产出              │
│ 5. 验证：重新渲染叠加 box 边框                  │
│    → VLM + 规则双通道复检                      │
│    → 通过则接受，不通过则回滚 / 降置信度         │
└─────────────────────────────────────────────┘
        ↓
每个 box 标记置信度（高 / 中 / 低）
```

### 6.3 动作空间（覆盖所有返工操作）

```
split          拆分联排
shrink_to_fit  收缩到点云支撑
add_box_at     在空隙处补设备
delete         删除误检
merge          合并同一设备的两部分
```

### 6.4 判别 vs 生成

VLM 永远只做判别：

```text
"这个框里是一个机柜还是两个柜子？"   → 判别
"这个空隙处有没有机柜？"             → 判别
"这个物体是机柜还是空调？"           → 判别
```

精确几何坐标来自 `fit_box_to_points` / `split_row` 等工具。

### 6.5 验证 — 智能体闭环的关键

每次修复后重新渲染，把 box 叠加回视图，再次验证：

```text
规则检查（尺寸 / 支撑度 / 对齐） + VLM 检查（看图判断）
两者都过才接受
规则不过 → VLM 说好也不算
最多重试 2–3 次 → 仍失败则传给人工
```

这确保 agent 不会"改坏"且不会在单个问题上死循环。

---

## 7. 阶段D：人工 3D 复核

### 7.1 关键改进：人工在 3D 层面复核，不再看上千张 2D 图

人工只在 3D 界面（渲染视图 + 俯视密度图 + box 叠加）上操作：

- 直接对候选框进行：加框 / 切分 / 删改 / 微调。
- 一次操作对应一个设备，而不是一个视角。
- 设备量（数百）远小于视角量（数千），标注操作量下降数量级。

### 7.2 人工只需处理低置信度项

```
高置信度项     → agent 自动接受
中置信度项     → agent + 规则确认后接受
低置信度项     → 人工复核
```

### 7.3 产出

人工复核结果与 agent 决策记录，共同作为 3D 标注数据源输出。

---

## 8. 数据飞轮（被低估的资产）

### 8.1 核心思想

人工返工 + agent 决策的过程，即在产出高质量 3D 标注：

```text
初始 box（错） + 人工/agent 修正（对） = 一对 3D 标注
```

- 每个机房 → 上百个设备的 after/before 对。
- 历史已返工机房 → 现成数据集。
- 跨机房 / 跨设备类型积累 → 扩大到任意场景。

### 8.2 用途

1. 训练 / 微调 3D 检测模型（替代 2D 标注）。
2. 迭代 agent 的判断规则（VLM prompt、几何规则参数）。
3. 扩大训练集，逐步降低人工复核比例。

### 8.3 长期目标

数据飞轮持续运转后，最终：

```text
新增机房 → 粗分割 + 规则 + agent 自动处理
→ 高置信度项自动接受
→ 低置信度项人工少量复核
→ 2D 标注需求降到最低甚至归零
```

## 9. 分阶段实施路线

| 阶段 | 内容 | 产出 | 进入下一阶段判据 |
|---|---|---|---|
| **阶段 0** | 规则后处理：行对齐 / 标准尺寸 / 支撑度过滤 | 量化消掉的返工量 | 返工量下降 40–60% |
| **阶段 1** | 自动 QA：规则 + agent 审计，只报问题不改 | 人工按 issue 定位返工，提速 | 审计 issue 列表准确率可用 |
| **阶段 2** | agent 提议修复，人工看 diff 一键接受 / 拒绝 | 积累"agent 提议 vs 人工裁决"数据 | 裁决数据显示 agent 修复准确率达标 |
| **阶段 3** | 高置信度修复自动应用，低置信度给人 | 真正的降本 | 人工复核比例降到可接受 |

每阶段独立产生价值，且上一阶段的裁决数据决定是否进入下一阶段。

## 10. 复用 FoundObj 的借鉴点

| FoundObj 机制 | 本项目对应物 | 借鉴程度 |
|---|---|---|
| superpoint 自底向上合并 | 阶段A 粗分割，去 RL 化 | ★★★★★ |
| 中心场一致性验证 | `check_completeness(box)` → 联排切分 / 粘连判据 | ★★★★★ |
| 基础模型当裁判 | VLM 判别"是否完整机柜"，跨机房免重训 | ★★★★ |
| 循环蒸馏成前馈 | 返工数据 → 训 3D 检测模型 | ★★★★ |
| 双奖励互补 + 自适应阈值 | 几何 + 外观双裁判、场景内自适应阈值 | ★★★ |
| PPO 强化学习 | 用规则 + VLM 代替 | 不借鉴 |

**不借鉴的部分**：

- PPO / RL：机柜合并策略可规则化。
- TRELLIS 级几何先验：只有标准设备，解析几何 / 轻量模型即可。
- 纯离线 + 依赖 RGB-D 投影 DINOv2：工程细节与 3DGS 不对齐。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| VLM 幻觉加框 | 所有 `add_box` 必须过点云支撑度检查，一票否决 |
| 修复震荡（A 影响 B，B 影响 A） | 按行为单位处理；每 issue 限最大重试次数；修不好直接给人 |
| 过度信任 VLM "通过" | 验证用规则 + VLM 双通道；规则不过 VLM 说好也不算 |
| 成本失控 | 规则先筛简单 case；VLM 只碰疑难件；证据图裁剪到局部区域 |
| 粗分割漏检 | 高召回阈值；结合行结构补全规则 |
| 跨机房域差距 | 判别式 VLM 比生成 / 分割更鲁棒；data 飞轮持续积累 |

## 12. 关键待确认问题（供评审）

1. **3DGS 能否导出点云 / Gaussian 中心**，以及能否按需渲染任意区域与任意视角？
2. **设备类型清单**：机柜 / 服务器 / 空调 / 门 / 其他，标称尺寸与摆放规范？
3. **历史返工数据是否有 before/after 记录**，可作评测与飞轮数据？
4. **人工目前返工的确切操作**（加框 / 切分 / 删改 / 微调），以映射到本方案的动作空间？
5. **机房场景差异**：点云密度、重建质量、灰暗 / 反光区域是否会导致候选过大 / 过碎？
6. **验收标准**：布局图"可用"的量化指标（设备类型 / 数量 / 位置误差），以便评估阶段进展？

## 13. 结论

本方案的核心思路是：

> **确定性几何规则和领域先验打底，VLM 只做判别与离散选择、几何工具执行精确定位，agent 闭环验证，人工只复核低置信度项，并把整个返工过程变成高质量 3D 标注的飞轮。**

相比现状，它能：

- 消除 2D 标注瓶颈（标注对象从"上千张视图"变成"数百个设备体"，且能换机房免重训）。
- 用规则消掉大部分分割错误，agent 处理疑难件，人工只复核低置信度项。
- 把返工历史变成训练数据，驱动模型持续改进，最终把人工降到最低。

如果评审确认本方向可行，下一步建议优先做**阶段 0（规则后处理）**，它能以最低成本快速验证方案价值，并为后续 agent 阶段打好地基。
